- 언어·계획은 매번 맞았다: LLM이 `blue_0 → on_top:green_0`을 골랐다.

## 원인

1. **손목 기준 픽셀을 잘못된 높이로 읽음 (15:54, 15:56).**
   - 기준 (295, 190)은 성공한 텔레옵 영상에서 잡았는데, 그 영상의 접근 높이를 8 cm로 봤다. 실제는 기본값 5 cm였다.
   - 그 결과 4 cm 위에서 "블록 바로 위"로 판단한 지점이 실제보다 2~4 cm 앞이었고, 그리퍼가 블록 너머에서 닫혔다.
   - 이 판단을 보고 사용자가 "로봇 쪽으로 1 cm"라고 보정했다.
2. **손목 카메라 색 기준이 탑뷰용 그대로였음 (run3, 아마 15:5x에도).**
   - 탑뷰의 반사광 오검출을 막으려고 파랑을 V≥180으로 올렸는데, 실행기도 같은 값을 썼다.
   - 손목 카메라에서 파랑 블록의 V 중앙값은 약 175라서 블록이 조각으로 잡혔고, 중심이 6~9 cm 틀렸다.
3. **블록이 팔 끝 거리에 있음 (run2, 4, 5, 6).**
   - 손목으로 잰 파랑의 실제 위치는 팔에서 약 0.25~0.26 m다. 수직으로 집을 수 있는 한계(약 0.26 m, 높이에 따라 다름)에 걸린다.
   - 접근 높이, 시험 이동, 보정 위치가 차례로 IK 범위를 벗어났다.
   - 이 거리에서는 블록이 손목 영상 위쪽 가장자리에 잘려 보여 중심과 보정량이 틀어진다.
4. **탑뷰 좌표만으로 집으면 빗나감 (16:03, 16:29).**
   - 손목 측정(run4 수렴 값)으로 보면, 이 구역(x≈0.22)에서 탑뷰가 실제보다 약 3 cm 로봇 쪽으로 짧게 본다.
   - 반면 0.20 m 근처(텔레옵 성공 위치)에서는 탑뷰가 맞았다. 판의 먼 쪽으로 갈수록 오차가 커지는 것으로 보인다.
   - 캘리브레이션은 판 모서리 4점에 정확히 맞춘 것이라 오차가 남을 수 있다.
   - 단, "약 3 cm"는 손목 기준 픽셀(원인 1을 고친 값)이 맞다는 전제의 추정이다. 탑뷰만으로 집어서 검증한 값은 아니다.
5. **기타**
   - 런치 직후 비전 노드가 잠깐 멈추는 경우가 있다(`no recent /vla/blocks`, 4번). 다시 보내면 됐다. 원인은 아직 모른다.
   - 매 동작마다 `arm did not settle` 경고가 난다. 동작마다 몇 초씩 늦어질 뿐, 실패 원인은 아니다.
   - 처음에는 오류가 나도 팔을 접지 않았다(run2).

## 고친 것 (실물 설정 `vla_executor/config/executor_real.yaml`; 시뮬 기본값은 그대로)

| 항목 | 내용 |
|---|---|
| 위치 결정 방식 | **손목 위치 맞추기 끔**(`wrist_center: false`). 탑뷰가 위치를 정하고, 손목은 잡았는지만 확인한다(원래 설계). 정렬 코드는 남김 |
| 손목 색 기준 | 파랑 S≥50 V≥120, 초록 V≥120(실행기만). 블록 조각을 하나로 합침 |
| 높이 | 집기 `grasp_z` 0.010 → 0.015(+5 mm, 사용자 요청). 접근 `approach_height` 0.08 → 0.06. 닿지 않으면 3 cm까지 1 cm씩 낮춤(`min_approach_height`) |
| 끝난 뒤 | 작업이 끝나거나 실패하면 그리퍼를 닫고 접는다(`close_at_observe`, `fold_on_error`) |
| 정리 스크립트 | `stop_vla.sh`가 실물 팔로워 `ros2_control_node`도 끈다 |
| 손목 정렬(꺼 둠) 보정 | 기준 높이 2 cm·픽셀 (300, 160), 블록 너머에서 먼저 보기, 시험 이동 5 mm(닿지 않으면 반대로), 정렬 사진 저장, 잰 오차를 쌓을 위치에도 적용 |
