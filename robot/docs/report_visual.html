"빨간 블록을 파란 블록 위에 쌓아줘" 같은 한국어/영어 명령을 받아, 카메라로 블록을 찾고, 언어 모델이 할 일을 정하고, 로봇 팔이 실제로 집어서 옮깁니다. Depth 카메라 없이 테이블 네 꼭짓점의 ArUco 마커만으로 블록의 실제 위치(m)를 계산합니다.

① 보기 — Depth 없이 마커 4개로 위치 재기

1
마커 4개를 찾는다
네 꼭짓점 마커의 실제 위치(로봇 기준 m)를 미리 알고 있습니다.
2
화면 ↔ 테이블 변환식을 만든다
마커 4점으로 "화면의 점 → 테이블 위 실제 위치" 변환(호모그래피)을 계산합니다. 카메라 높이도 함께 역산됩니다(0.75 m, 실제와 일치).
3
색으로 블록을 찾는다
빨강·초록·파랑·노랑 영역을 찾고, 블록이 회전한 각도도 구합니다.
4
블록 높이만큼 보정한다
카메라는 블록 윗면을 보므로, 원근 때문에 생기는 위치 밀림(최대 ≈7 mm)을 카메라 위치를 이용해 보정합니다.
정확도 — 4개 블록 모두 시뮬레이터의 실제 위치와 비교해 오차 0.5 ~ 2.1 mm, 회전 각도 오차 0°.

언어 모델이 돌려주는 것

      "place": "on_top:red_0" } ] }

→ 코드가 red_0의 위치와 높이(+2.5 cm)로 좌표를 계산

개선 전후 비교 (명령 10개, gemma4:e2b)

무엇을 바꿨나? 처음에는 모델이 블록 이름 자리에 "id"라는 글자를 그대로 쓰거나, 장소 이름을 빠뜨리는 실수가 있었습니다. 지금은 실제로 보이는 블록 이름과 허용된 장소 목록 안에서만 고를 수 있도록 출력 형식을 매번 새로 만들어 강제합니다. 작은 모델(2B급)로도 실수가 사라졌습니다.

손목 카메라로 "제대로 잡았나?" 확인

블록을 들어 올린 직후 그리퍼에 달린 손목 카메라로 손가락 사이를 봅니다. 잡은 블록은 카메라 바로 앞에 있어 화면 가운데 상자를 거의 가득 채우고, 놓쳤다면 상자가 비어 있습니다. 상자 안에서 집으려던 색이 60% 이상이면 통과, 아니면 집게를 열고 물러난 뒤 실패로 보고합니다.

함께 개선된 점

• 쌓을 때 4 mm 위에서 놓기 → 아래 블록이 튕겨 나가지 않음
• 놓을 때 집게를 조금만 열기 → 블록이 날아가지 않음
• 쌓기 성공률 2/3 → 8/9
• 일반 이동 3/3 유지 (오차 4–6 mm)

남은 과제 — 위에서 내려다보는 카메라로는 쌓은 블록 아래가 "가려진 것"인지 "튕겨 나간 것"인지 구분하지 못합니다. 놓은 뒤 손목 카메라로 위 블록의 크기를 재서 실제로 쌓였는지 확인하는 기능을 다음에 추가할 계획입니다.

캘리브레이션 — 실제 환경에 맞추기

카메라, 마커 위치, 조명, 손목 카메라는 설치할 때마다 달라집니다. 이를 맞추는 4단계 도구를 만들었고, 시뮬에서 정답과 비교해 검증했습니다. 결과는 설정 파일로 저장되고, 실행할 때 calib_dir로 지정하면 자동으로 적용됩니다.

시뮬 검증 결과

단계검증 방법결과
1. 카메라 렌즈시뮬 카메라의 실제 값과 비교초점거리 오차 0.03 %
2. 블록 색4색 블록 측정4색 모두 인식, 98–100 %, 색끼리 겹침 없음
3. 마커 ↔ 로봇마커 위치를 일부러 2° 돌리고 1.4 cm 옮긴 뒤 실행회전 2.04° 되찾음, 맞춤 오차 3 mm
4. 손목 카메라잡음과 놓침 구분잡음 95–100 % vs 놓침 6 % → 확실히 구분
알아둘 점 — 3단계는 카메라 좌표를 "로봇이 실제로 블록을 놓는 위치"에 맞춥니다. 그래서 카메라와 로봇 사이의 일치는 0–1 mm로 좋아지지만, 시뮬에서는 로봇이 늘 약 9 mm 짧게 놓는 버릇까지 함께 반영되어 절대 위치는 그만큼 이동합니다. 블록 위에 쌓기·옆에 놓기처럼 블록 기준 작업에 유리한 방식입니다.

다음 단계

시뮬레이션에서 더 할 일

• 놓는 위치의 일정한 어긋남(≈4 mm) 보정
• 쌓기 성공률 높이기 (내려놓는 속도 낮추기 등)
• 명령 시나리오를 늘려 성공률 통계 측정
• 더 큰 언어 모델과 비교 (16 GB GPU 안에서)

실물 로봇으로 옮길 때 필요한 것

• 마커: 마커 사이 거리만 자로 재기 (로봇 기준 위치는 캘리브레이션 도구가 구함)
• 카메라: 장치 번호, 해상도 → 렌즈 캘리브레이션 도구
• 블록: 실제 크기, 색 → 색 캘리브레이션 도구
• 로봇: U2D2 포트, 그리퍼 잡는 힘 확인
• 원하는 명령 예시 5~10개

실물 이전이 쉬운 이유 — 카메라 인식, 언어 모델, 검증 로직은 시뮬레이션과 실물에서 그대로 쓰입니다. 바뀌는 것은 설정 파일 값(마커 좌표, 색 범위, 잡는 높이)과 카메라·로봇 드라이버 실행뿐입니다.
