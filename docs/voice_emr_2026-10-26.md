# EMR 음성 기능 정리 (KT-48, 2026-10-26)

- 대상: EMR 웹·로봇 팀원, 이어서 작업할 Claude. 오늘 EMR에 넣은 음성 기능이 **무엇을 하고, 어떻게 켜고, 무엇이 남았는지** 한 장으로 정리했다.
- 자세한 파일·클래스는 [`architecture/README.md`](architecture/README.md) 4.14, 결정 사항 전체는 `emr/CLAUDE.md` "음성 배송 예약", 속도 비교 근거는 [`voice_performance_basis_2026-10-26.md`](voice_performance_basis_2026-10-26.md).
- 출처: 저장소 밖 단독 검증 모듈 `~/voice_module`(10-14)을 EMR 계층(api → services → clients)에 맞춰 옮겼다. 원본 모듈은 그대로 두었다.

## 1. 한눈에 보기

| 기능 | 무엇을 하나 | 주소 | 엔진 |
|---|---|---|---|
| **말로 배송 예약** | 간호사가 말하거나 문장을 쓰면 목적지·품목·수량 **초안**을 만들어 배송 예약 폼을 채운다. 예약은 간호사가 확인하고 '예약'을 눌러야 생긴다 | `POST /api/v2/voice/parse`(녹음) · `POST /api/v2/voice/parse-text`(문장) | Gemini(받아 적기 + 추출 1회) |
| **안내 음성 API** | 문장을 주면 읽은 음성(WAV)을 돌려준다. 안내 방송용 | `POST /api/v2/voice/speak` | Gemini TTS + 서버 메모리 캐시 |
| **화면 안내 음성** | 상단 '🔇 안내 음성'을 켜면 배송 출발·도착·실패와 음성 초안 결과를 브라우저가 읽어 준다 | (서버 없음) | 브라우저 내장 speechSynthesis |

- 음성 API는 **`/api/v2`**에 있다(사용자 결정 10-26: 음성은 v2에서 고도화, v1 주소는 없앰).
- 기본은 **꺼져 있다**(`VOICE_PARSER=disabled` → 503 `voice_disabled`).

## 2. 사용자 결정 (10-26)

| 항목 | 결정 |
|---|---|
| STT 엔진 | **Gemini로 시작**. 로컬(faster-whisper + Ollama)은 같은 인터페이스(`VoiceParser`)로 나중에 바꾼다 |
| 쓰는 화면 | **간호사 배송 예약만**. 병상 단말은 범위 밖 |
| TTS | 화면 안내는 **브라우저 내장**. 같은 날 추가 요청으로 서버 안내 음성 API(`/speak`, Gemini TTS) |
| 약품 | **받되 자동 확정하지 않는다.** 원본 모듈은 약품이면 품목을 비웠는데, 지금 간호사 품목이 모두 약품이라 바꿨다. 음성으로 채운 약품 줄은 '확인함'을 표시해야 예약 버튼이 켜진다 |
| 마이크를 못 쓸 때 | 브라우저 마이크는 localhost·HTTPS에서만 된다. 다른 PC(`http://<IP>:5173`)는 **문장 입력**으로 대신하고 안내만 띄운다 |
| 주소 | 음성은 `/api/v2`. 고도화(성능 비교·스트리밍·로컬 TTS·캐시 미리 채우기)는 v2에서 |

## 3. 흐름

```
간호사 🎤 말하기 / 문장 입력
  → POST /api/v2/voice/parse(·parse-text)
  → Gemini: 받아 적기 + {품목 이름·수량, 장소, 약품 여부} JSON
  → voice_matcher가 EMR 목록과 맞춤
      · 비품: requestable_by=nurse
      · 장소: robot_only가 아닌 것
      · 정확 일치 → 포함 → 유사도 0.75. 1·2위가 가까우면 확정하지 않고 후보 3개
  → 초안(목적지·품목 줄·경고) → 배송 예약 폼을 채움
  → 간호사가 확인(약품은 '확인함') → '예약' = 기존 POST /api/v1/deliveries
```

- 경고 코드: `medication_check`(약품 확인) · `item_unmatched`(품목 확정 못 함) · `no_items` · `location_missing` · `location_unmatched` → 하나라도 있으면 `needs_review`
- 같은 비품을 두 번 말하면 수량을 합친다(예약은 같은 비품을 한 줄만 받는다).
- 음성 API는 **DB에 쓰지 않는다** — 예약·재고는 '예약' 버튼에서만 바뀐다.

## 4. 켜고 끄기

`emr/.env`에 넣고 api만 다시 띄운다(DB는 그대로):
```bash
VOICE_PARSER=gemini          # disabled면 /api/v2/voice/* 가 503 voice_disabled
GEMINI_API_KEY=<발급받은 키>   # .env에만. 문서·커밋·로그에 넣지 않는다
docker compose up -d api
```

| 설정 | 기본값 | 뜻 |
|---|---|---|
| `VOICE_MODEL` | `gemini-3.8-flash` | 받아 적기·추출 모델 |
| `VOICE_TIMEOUT_SECONDS` | 20 | 넘으면 503 `voice_unavailable` |
| `VOICE_TTS_MODEL` | `gemini-3.8-flash-tts` | 안내 음성 모델 |
| `VOICE_TTS_VOICE` | `Kore` | 기본 목소리(요청마다 `voice`로 바꿀 수 있음) |
| `VOICE_TTS_STYLE` | 병원 안내 방송처럼 차분하게 | 말투 지시 |

`/speak` 예:
```bash
curl -X POST http://<서버>:8000/api/v2/voice/speak -H 'Content-Type: application/json' \
  -d '{"text":"4인실 왼쪽에 배송 로봇이 도착했습니다."}' -o arrive.wav
# 같은 문장·목소리는 캐시(최근 64개) — 응답 헤더 X-Voice-Cache: hit|miss
```

## 5. 보안·개인정보

- **켜면 녹음·문장이 Google 클라우드(Gemini)로 나간다.** 시연·시험 동안만 쓰고, 환자 정보를 말하거나 `/speak`에 넣지 않는다. 무료 티어 입력은 Google 서비스 개선에 쓰일 수 있다.
- 서버 로그에는 **받아 적은 문장·품목·안내 문장을 남기지 않는다** — 길이·처리 시간·`needs_review`·캐시 여부만.
- 간호사 로그인이 필요하다. 다만 지금 개발 스택은 `AUTH_DISABLED=1`이라 같은 망 누구나 호출할 수 있다(키 할당량을 쓴다) — 시험이 끝나면 `VOICE_PARSER=disabled`.
- 운영 전에는 로컬 STT·TTS로 바꿔 음성이 PC 밖으로 나가지 않게 한다(이슈 B6).

## 6. 확인한 것 (10-26)

- 백엔드 테스트 **203개 통과**(음성 34개: 가짜 파서·가짜 TTS, Gemini에 안 보냄). 프론트 typecheck·lint·build 통과.
- **실제 Gemini**(이 서버):
  - "4인실 왼쪽에 A 약품 두 개" → 4인실 왼쪽 · A 약품 ×2, 약품 확인 경고
  - "수술실로 주사제 하나랑 비 약품 세 개" → 수술실 · 주사제 ×1, B 약품 ×3
  - "약품 좀 갖다줘" → 품목 후보 A·B·C, 장소 없음 경고
- **브라우저**(headless, 가짜 마이크에 TTS 녹음 4.3초 재생): 녹음 → 받아 적기 → 폼 채움 → 예약 버튼 막힘 → '확인함' 뒤 켜짐. 실제 예약은 누르지 않았다.
- **화면 안내 음성**: 토글·초안·도착 알림 문장이 `ko-KR`, "Google 한국의" 목소리로 나감. 이 과정에서 Linux espeak의 콘칸어(`kok`)가 한국어로 잘못 골리던 문제를 고쳤다.
- **속도**(첫 소리까지):

  | 엔진 | 시간 |
  |---|---|
  | Gemini TTS 새 문장 | 5.7~7.9초 |
  | 캐시 | 0.007초 |
  | 브라우저 내장 | 0.3~0.6초 |
  | espeak | 0.05~0.1초 |

  STT는 6~7초. 자세한 표·근거는 [성능 근거 문서](voice_performance_basis_2026-10-26.md).
