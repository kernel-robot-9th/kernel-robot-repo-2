# 시나리오 ② 부하 시험 — 1분에 5번 신청, 시간 제한 없음 (2026-10-30)

사용자 요청: "OMX 가상으로 배송 1분 5건을 넣는 테스트 시나리오, 시간 제한 무제한". 범위는 EMR + FMS + 실제 Pinky. OMX는 가상이다.

## 0. 무엇을 보나

- 신청이 배송보다 빨리 들어올 때 EMR → FMS 주문이 밀리지 않고 다 넘어가는지 본다.
- 오래 돌려도 FMS가 교착 없이 실제 Pinky 3대를 계속 돌리는지 본다. 10-30 시뮬레이터에서는 8분 만에 교착이 났다(`logs/2026-10-30_sim/issues.md` 1번).
- 간호사 화면(신청, '받았습니다', 지도 로봇 카드)이 신청 수백 건에서도 버티는지 본다.

**10-30 2차에서 찾은 EMR 버그(고침)**: 다 보낸 예약이 50건을 넘으면 새 신청이 FMS로 가지 않았다(`logs/2026-10-30_sim/issues.md` 6번). 이 시험은 그 회귀 확인용이기도 하다.

**주의: 신청이 배송보다 훨씬 빠르다.** 장면 A 한 묶음(병동 3곳)은 실물로 약 10분 걸린다. 그래서 FMS 대기 주문은 계속 늘어난다. 끝내는 시점은 사람이 정한다.

## 1. 환경

| 무엇 | 값 |
|---|---|
| Pinky | 실제 3대. FMS 도커 `--real-table`, **호스트 네트워크**(공유 연결을 다시 올린 뒤 도커 → 10.42.0.x가 막혀서). IP 고정 `/etc/NetworkManager/dnsmasq-shared.d/pinky-robots.conf` |
| OMX | 가상. FMS `POST /api/control {"auto_omx": true}`가 `ready`·`loaded`를 보낸다. EMR `.env`는 `FMS_OMX_ENABLED=0` |
| 간호사 | N003. 화면은 '물품 신청'과 '병원 지도' 두 개 |
| 시작 전 | Pinky 3대 `pose_confirmed`(아니면 `POST :8080/set_pose {"find": true}`), FMS 로봇 3대 `idle`·오류 없음, 남은 신청 없음 |

## 2. 진행

1. **12초마다** 간호사 화면에서 '즉시' 신청을 한 번 넣는다. 모양은 무작위다(시드 20261030).
   - 장면 A: 병동 3곳에 물품 1개씩
   - 장면 B: 병동 3곳, 첫 병동만 2개
   - 병동 1곳 또는 2곳에 1개씩
   - 병동은 101~108호와 수술실 중에서, 물품은 A·B·C 약품과 주사제 중에서 고른다.
2. FMS가 묶음을 만들어 배차한다(한 대에 최대 3개). 가상 OMX가 적재하고, 실제 Pinky가 약제실에서 정밀 주차한 뒤 병실로 간다.
3. 도착 창이 6초 보이면 화면에서 '받았습니다'를 누른다. 40초 안에 못 누르면 API로 대신 받고 `대신 받음`으로 기록한다.
4. 약품 재고가 30보다 적어지면 100으로 채운다(`재고 보충` 기록). 시간 제한이 없어 재고가 바닥나지 않게 하려는 것이다.
5. **로봇 오류(fault)는 풀지 않는다.** 기록하고 FMS 상태를 JSON으로 저장할 뿐이다. 풀려면 사람이 현장을 확인한 뒤 `POST :8770/api/control {"clear_fault": "R<번호>"}`를 보낸다(10-30 장면 A 2차의 협로 `rotate_err`).
6. **끝내기**: `touch <녹화 폴더>/stop`. 새 신청을 멈추고 로그와 영상을 만든다. 이미 넣은 신청은 FMS가 계속 처리한다.

## 3. 기록

- 로그: `logs/2026-10-30_real/load_<시각>/`
  - `summary.md`
  - EMR 배송 기록, FMS 주문, FMS 이벤트, EMR api 로그

  - 오류가 나면 `fms_state_fault_*.json`
- 영상: 1초에 한 장씩 두 화면을 찍고, 20배속으로 만든다. 디스크는 1시간에 약 0.7 GB를 쓴다.

## 4. 끝낸 뒤 되돌리기

- OMX 실물로 되돌리기
  - EMR `.env`: `FMS_OMX_ENABLED=1`로 바꾼 뒤 `docker compose up -d api`
  - FMS: `POST /api/control {"auto_omx": false}`
- 남은 신청: FMS를 다시 켜면 FMS 주문이 사라진다(`issues.md` 4번). 정리 방법(실패 처리 + 재고 복구)은 사용자가 정한다.
