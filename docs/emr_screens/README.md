# EMR 대표 화면 5장 (2026-11-03) + 영상 6편 (2026-11-02·03)

병원 간호사용 비품·배송 웹(EMR)이 어떻게 생겼는지 한눈에 보는 화면 모음이다. 주소는 이 서버 기준 `http://192.168.129.135:5173`.

- 화면 5장은 2026-11-03에 지금 화면(1280×800)으로 다시 찍었다(10-23 판을 교체). 맵은 "Pinky 아레나" 평면도, 수령은 "받았습니다" 버튼.
- 시험용으로 **로그인을 꺼 둔 상태**라 주소만 열면 들어가진다. 화면은 관리자 김간호(N001).
- 2번 도착 창과 10·11번 영상의 배송 #418은 찍으려고 만든 시험 신청이다 — 실제 로봇은 움직이지 않았고, FMS가 보내는 '배송 완료' 신호를 EMR에 직접 보내 도착으로 만들었다(가상 도착, 11번 절). 기록에는 #418이 받음으로 남아 있다.
- 1번 목록·3번 지도는 녹화 브라우저에서만 응답을 고쳐 찍었다 — 취소된 신청 줄을 숨기고, 지도 로봇은 연결됨·대기로(찍을 때 FMS 상태 신호가 끊겨 있었다). 위치·피로도·오염도는 실제 값. 4번 병상 화면은 시험 단말 "105호-1"을 만들어 찍고 바로 지웠다.

## 1. 물품 신청 목록

![물품 신청 목록](01_deliveries.png)

본인 신청 목록. 행마다 배송 단계(신청 → 준비 → 출발 → 도착 → 받음)와 받은 시각이 보인다. 아직 보내기 전(신청)이면 **변경**할 수 있다(취소 버튼은 11-02에 화면에서 뺐다). 오른쪽 위 **+ 요청하기**로 보낼 시간·병동·품목을 넣는다.

## 2. 로봇 도착 → "받았습니다"

![로봇 도착](02_arrived_received_button.png)

FMS가 배송 완료를 알리면 신청한 간호사 화면에 창이 뜬다. 물건을 받고 **받았습니다**를 누르면 수령이 끝난다. 창에 받을 수 있는 시간(도착 후 5분)이 보이고, 오른쪽 아래는 출발·도착 알림.

## 3. 병원 지도 — Pinky 아레나

![병원 지도](03_map_pinky_arena.png)

병실·약제실·수술실 같은 장소(파란 점과 도착 방향)와 운반 로봇 위치(주황 화살표, FMS가 1초마다 보냄). 오른쪽은 등록된 로봇, 지도 아래는 로봇 카드(지금 있는 곳·피로도·오염도).

## 4. 병상 화면 (환자 요청)

![병상 화면](04_bedside.png)

병상 태블릿에서 환자가 필요한 물품(환자용 품목만)과 수량을 골라 **요청하기**. 간호사 승인 없이 바로 배송이 생기고, 로봇이 도착하면 이 화면에 "받았습니다" 버튼이 뜬다. 관리자가 환경 설정의 '병상 단말' 탭에서 병상을 등록하고 키를 발급한다.

## 5. 배송 기록 (관리자)

![배송 기록](05_delivery_log.png)

배송마다 누가 언제 무엇을 했는지(간호사 신청·변경, 로봇 준비·출발·도착, 받음, 실패). 사건·로봇·신청 간호사·배송 번호·날짜로 거른다. 기록은 지우지 않는다.

## 6. 여러 병동 신청 + 관리자 메모 (영상)

[06_multi_ward_request.mp4](06_multi_ward_request.mp4) — 1280×800, 40초

1. 물품 신청 화면에서 **+ 요청하기** → **시간 지정**으로 보낼 시간을 내일 10:00으로 둔다.
2. 병동 1에 101호 · 이불 1개를 넣는다.
3. **+ 병동 추가** → 병동 2에 같은 101호를 고르면 "같은 병동이 두 번 들어 있습니다" 경고가 뜬다 → 103호로 바꾸고 이불 1개를 넣는다.
4. **2개 병동 신청** → 목록에 병동마다 한 건씩 두 건(#363 101호, #364 103호)이 생긴다. 도착·수령·알림은 병동별로 따로 간다.
5. 환경 설정 > 장소 탭: 장소 이름은 "101호"이고, "4인실 왼쪽" 같은 설명은 **관리자 메모** 칸에만 보인다(관리자 화면 전용).

신청 시각을 내일로 잡아서 FMS(실제 Pinky)로는 가지 않았다. 녹화 뒤 두 건을 바로 취소했다(재고는 원래대로). 목록의 다른 행은 그날 시험 배송이다.

## 8. 개발 화면 — API 문서 (영상)

[08_dev_api_docs.mp4](08_dev_api_docs.mp4) — 1280×800, 1분 6초. FastAPI·Swagger가 코드에서 자동으로 만드는 API 문서를 자막과 함께 보여 준다.

| 순서 | 화면 | 보여 주는 것 |
|---|---|---|
| 1 | EMR API 문서 `:8000/docs` | 기능별(auth·supplies·deliveries·locations·robots·fms·omx …) 묶음을 훑어봄 |
| 2 | `POST /api/v1/deliveries/multi` | 여러 병동 신청의 설명·요청 본문·응답 코드(400 같은 병동, 409 재고 부족) — 펼쳐 보기만 |
| 3 | `GET /api/v1/locations` | Try it out → Execute. 응답에 이름("101호")과 `admin_note`가 따로 옴 |
| 4 | `POST /api/v1/fms/robot-status` | FMS → EMR 받는 곳(1초마다 로봇 상태, 지도 위 위치) — 펼쳐 보기만 |
| 5 | 팀원 FMS API 문서 `:8770/docs` | 주문·묶음·상태·방·지도 API 목록 |
| 6 | `POST /api/v1/orders` | EMR이 보내는 주문 형식 — 펼쳐 보기만(실제 Pinky와 연결되어 있어 실행하지 않음) |
| 7 | `GET /api/v1/rooms` | 실행. 방 번호(101호 …) ↔ 주행 노드 |

GET만 실행했다. 팀원 FMS 관제 화면(`:8770/`)은 실물 시험 중 오류 상태가 찍혀서 넣지 않았다.

## 9. 배송 웹 소개 (영상)

[09_delivery_web_intro_2026-11-02.mp4](09_delivery_web_intro_2026-11-02.mp4) — 1280×872(화면 1280×800 + 아래 자막 띠), 45초. 1분 32초 녹화를 2.04배로 빠르게 하고 장면마다 자막을 넣었다(자막은 화면을 가리지 않게 아래 띠에). 마우스 커서로 따라간다.

- 만들기: `bash tools/demo/intro_video.sh <out.mp4> [작업 폴더]` — `intro_cursor.mjs`로 찍고(장면 자막 시각을 `captions.json`에 남김) ffmpeg으로 빠르게·자막. `SPEED`로 배속을 바꾼다(지금 영상은 `SPEED=2.042`). **실제 배송 중에는 찍지 않는다** — 도착 창이 화면을 가린다(11-02 밤 #412~417 실물 배송 때 겪음)

1. 물품 신청 목록 → 받음까지 끝난 신청의 **자세히**(단계별 시각)
2. **+ 요청하기** → 즉시 → 병동 1(105호 · A 약품 2개 · 환자복) → **+ 병동 추가** → 병동 2(103호 · C 약품) → 신청 버튼 위에서 멈추고 **닫기**(신청은 누르지 않음 — 누르면 실제 Pinky로 주문이 간다)
3. 병원 지도 — 로봇 위치와 아래 로봇 카드(피로도·오염도)
4. 배송 기록 → 다시 물품 신청

2026-11-02 손봄(지금 영상은 오후 10시 43분 녹화본에 자막 시각을 손으로 맞춰 넣음): 앞뒤 빈 시간 줄임·페이드, 목록(select)은 펼친 목록을 그려 커서로 고르는 모습이 보이게 했다. **녹화 브라우저에서만** 응답을 고쳐 찍었다 — 신청 목록의 취소된 줄은 숨기고, 지도 로봇은 연결됨·대기로 보이게 했다(그때 실제 로봇 3대는 FMS에서 `error` 상태였다). DB·FMS는 바꾸지 않았다. 위치·피로도·오염도는 실제 값이다.

## 10·11. 배송 요청 · 배송 받음 (최종 영상용, 2026-11-03)

[10_delivery_request_2026-11-03.mp4](10_delivery_request_2026-11-03.mp4) — 10초(2배속). **+ 요청하기** → 시간 지정(오늘 10:00) → 105호 → A 약품 → **신청** → 목록 맨 위에 #418(신청)이 생긴다.

[11_delivery_received_2026-11-03.mp4](11_delivery_received_2026-11-03.mp4) — 9초(1배속). 목록을 연 채 도착 → '배송이 도착했습니다' 창과 출발·도착 알림 → **받았습니다** → '받음 확인' 알림, #418 단계가 받음까지 채워진다.

둘 다 1280×872(화면 + 아래 자막 띠), 마우스 커서. **가상 도착**: 실제 Pinky가 움직이지 않게, #418을 만든 직후 그 물품의 FMS 주문 줄(`fms_orders`, 주문 번호 `demo-418-1`, FMS 로봇 1)을 DB에 직접 넣어 EMR이 실제 FMS로 주문을 보내지 않게 했다. 그다음 FMS가 보내는 것과 같은 `order_delivered` 이벤트를 `POST /api/v1/fms/events`로 보내 출발·도착이 되었고, 받았습니다는 화면에서 실제로 눌렀다. 실제 FMS·Pinky·OMX로는 아무것도 가지 않았다(이때 EMR의 OMX 자동 연동은 꺼져 있음, `FMS_OMX_ENABLED=0`).
