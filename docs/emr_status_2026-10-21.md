# EMR 웹 진행 현황 (2026-10-21)

- 대상: 팀원 전체(웹·로봇·OMX). FMS(관제) 작업을 시작하기 전에 EMR이 어디까지 됐는지 맞춘다.
- 기준: `emr/CLAUDE.md`(결정 사항·로드맵), 코드, 지금 띄워 둔 스택(docker `db`·`api`·`web`). 자세한 API는 `docs/api_contract_delivery_2026-10-20.md`.
- 접속: `http://<서버 IP>:5173` · API 문서 `:8000/docs` · 개발 계정 N001(관리자)·N002(간호사)

## 1. 요약

- 로드맵 **1단계**(맵·장소), **2단계**(배송 배정·진행), **4단계**(배송 기록 — 2026-10-21 추가)를 끝냈다. **5단계**(알림)는 일부만 됐다.
- 간호사가 배송을 예약하면, 예약 시각이 지난 뒤 관제 PC 배송 실행기가 그 배송을 가져가(claim) Pinky를 보낸다. 도착하면 간호사 화면에 뜨는 **일회용 수령 마커**를 로봇이 읽어 수령을 알린다. 단계마다 간호사에게 실시간 알림이 간다.
- **아직 안 된 것**: 로봇 상태 보고와 관제 화면(3단계), 로봇 키·끊김 기록(4단계 나머지), 여러 대 운영(6단계), 실물 Pinky 종단 시험, 운영 배포 준비.

## 3. 로드맵 진행

| 단계 | 내용 | 상태 |
|---|---|---|
| 1. 맵·장소 | 맵 업로드, 맵 위에서 장소 찍기 | ✅ 완료 (10-19) |
| 2. 배송 배정·진행 | 실행기가 예약 시각이 지난 배송부터 하나씩 가져감(claim) → 출발 → 도착(일회용 마커) → 수령. 실패하면 재고 복구. 로봇 복귀 장소 | ✅ 완료 (10-20). 실제 EMR + 가짜 Nav2로 확인 |
| 3. 로봇 상태 보고 | 위치·배터리 보고(`POST /robot/status` 안), 마지막 연락 시각, 끊김 표시, 맵에 실시간 표시 | ❌ 시작 전 |
| 4. 상태 로그 DB | **배송 기록**: 간호사 예약·변경·취소 + 로봇 출발·도착·수령·실패를 `delivery_events`에 남김. 관리자 '배송 기록' 화면(거르기·더 보기), 간호사 본인 배송 '기록' 창. 지우지 않음 | ✅ 완료 (10-21). 로봇 키·끊김 기록은 3단계 뒤 |
| 5. 알림 | 재고 부족(모두), 배송 출발·도착·수령·실패(예약 간호사), 실패(관리자에게도) | 🔶 일부. 배터리 부족·끊김 알림은 3단계 뒤 |
| 6. Pinky 여러 대 | 여러 로봇에 배정 | ❌ 시작 전. 여러 로봇이 동시에 claim해도 한 배송은 한 로봇에만 간다(실제 스택에서 확인). 로봇마다 ROS 도메인을 나누는 안이 있음(`docs/pinky_multi_robot_2026-10-20.md`) |

나중에 할 것: 적재(사람 확인 → OMX 로봇팔), 유효기간 알림, 운영 배포.

## 4. 배송 흐름 (2단계)

```
reserved    간호사 예약        ─ 간호사 취소 → cancelled (reserved에서만)
   ↓ 예약 시각 지남 · 실행기 claim
dispatched  출발               ─ 주행 실패 · 금지 장소 → failed (재고 복구)
   ↓ Nav2 도착
arrived     도착 · 일회용 마커  ─ 5분 미수령 → failed (재고 복구)
   ↓ 로봇이 마커를 읽음
received    수령
```

- 일회용 수령 마커: ArUco `DICT_4X4_250`의 50–249. 도착할 때 EMR이 무작위로 정하고, **예약한 간호사 화면에만** 보인다. 간호사 신분증 마커(0–49)로는 받을 수 없다.
- 로봇은 `X-Robot-Api-Key`(로봇별 키)로 `/api/v1/robot/...`만 부른다: `GET /robot/me`, `POST /robot/deliveries/claim`, `POST /robot/deliveries/{id}/progress`, `POST /robot/deliveries/{id}/receipt`.
- 알림은 저장하지 않고 실시간(SSE)으로만 보낸다. 출발·도착은 파란 토스트, 수령은 초록, 실패는 빨강이다. 마커 창은 배송 목록을 보고 띄우므로 새로고침해도 다시 보인다.

## 7. FMS 작업과 이어지는 곳

- **3단계**(로봇 상태 보고)가 FMS와 바로 겹친다.
  - 지금 `robot/src/fms/robot_monitor`(`:8090`)가 로봇 위치·배터리를 모으지만 EMR로 보내지 않는다.
  - 실행기나 모니터가 EMR에 위치·배터리를 보내는 것부터 시작한다.
- **6단계**(여러 대)는 실행기를 로봇마다 하나씩 띄우고, 로봇마다 ROS 도메인을 나누는 안으로 간다.
- 두 단계 모두 **들어가기 전에 API 계약(필드·주기·오류 코드)을 문서로 먼저 맞춘다.** 2단계 때와 같은 방식이다.
