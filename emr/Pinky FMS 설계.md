# Pinky FMS 설계

Oct 26, 2026 · @lee

## 개요

FMS는 관제 PC가 넘긴 약품 배송 주문을 받아 어느 핑키가 어떤 순서로 어느 길로 갈지 정하고, 길을 예약해 가며 구간 단위로 로봇을 움직인다. 핑키는 FMS가 준 구간만 주행하고 상태를 보고한다.

| 역할 | 맡는 일 | 맡지 않는 일 |
| --- | --- | --- |
| 관제 PC | 클라이언트 주문 접수, 주문 진행 상태 표시, 핑키 주차 끝 알림 수신, OMX 적재 지시, 적재 완료를 FMS에 전달 | 로봇 선택, 좌표·경로 |
| FMS | 지도(그래프) 관리, 오염도·배터리·적재 수 관리, 배송 묶음, 배차, 경로 계획, 구간 예약, 노는 로봇 비키기 | 실제 주행 제어 |
| 핑키 | 받은 구간 주행(Nav2 / 벽 따라가기 / 차선 / 정밀 주차 / 제자리 회전), 위치·진행을 FMS에 보고, 약제실 주차 끝을 관제 PC에 알림 | 경로 계획, 다른 로봇 고려 |
| OMX | 관제 PC 지시로 핑키 위에 약을 내려놓음 | 로봇 호출 |

이번 문서에서 다루지 않는 것: 실패 처리(로봇 멈춤, 연결 끊김, 적재 실패). 단, 끊긴 로봇의 예약은 풀지 않고 막아 둔다는 원칙만 정해 둔다.

## 확정된 규칙

아래 규칙은 FMS가 배차할 때와 구간을 내줄 때 모두 검사한다. 오염도·배터리·적재 수는 실제 센서가 아니라 FMS가 관리하는 값이다.

| 분류 | 규칙 | FMS가 검사하는 시점 |
| --- | --- | --- |
| 배송 | 약품은 항상 약제실(OMX)에서 싣는다. 주문 1건 = 약 1개 | 묶음 만들 때 |
| 적재 | 한 번에 최대 **3개**. 여러 병실을 연이어 들른다. 구간은 약제실→병실 또는 병실→병실 | 묶음 만들 때 |
| 여분과 새 주문 | 약제실에서 3개까지 채운다(배정 주문 + 여분). 여분이 있는 로봇은 배송 중에도 새 주문을 받는다 | 새 주문이 들어올 때 |
| 싣고 있음 | 약품이 1개라도 남아 있으면 ‘싣고 있음’ (여분도 포함) | 교행통로에 들어갈 때 |
| 병실 작업 완료 | 병실에서 제자리 1바퀴(360°) 회전하면 그 병실 배송 완료, 다음 작업 가능 | 로봇이 회전 구간 완료를 보고할 때 |
| 오염도 증가 | 병실에 도착하는 순간 1인실 +10, 4인실 +50. 약제실·수술실은 0 | 도착 보고 때 |
| 오염도 한도 | 경로 어느 지점에서도 100 이하(100은 허용). 넘게 되는 작업은 배정하지 않음 | **배차할 때 미리 계산** |
| 오염도 초기화 | 충전 앞 대기장소 POCKET (200,150)에 5초 머물면 0 | 로봇이 5초 머문 뒤 |
| 수술실 | 오염도 0일 때만 진입 | 배차할 때, 진입 구간을 내줄 때 |
| 배터리 소모 | **병실 하나** 배송(회전 완료)당 −10 | 회전 완료 보고 때 |
| 배터리 한도 | 20 이하면 약제실 방문 금지. 배터리가 0 아래로 내려가지 않도록 들를 병실 수 × 10 ≤ 배터리 (설계에서 추가) | 배차할 때 |
| 충전 | CHARGER 도착 후 10초 뒤 100 (설정값) | 충전 도착 때 |
| 교행통로 | 두 로봇이 모두 싣고 있으면 교행 금지. 하나라도 비어 있으면 가능. 같은 방향으로 따라가는 것은 허용 | 통로에 들어갈 때 |
| 협로 | 교행 불가. 한 번에 1대 | 협로에 들어갈 때 |
| 우선순위 | 주문에 우선도 없음. 들어온 순서대로 | 묶음 만들 때 |
| 로봇 대수 | 최대 3대 | — |

수술실 규칙 때문에 수술실이 낀 묶음은 두 순서 중 하나가 된다: ① 오염도 0으로 출발 → 약제실 → 수술실 먼저, ② 다른 병실을 돈 뒤 POCKET에서 0으로 만들고 수술실. FMS가 더 짧은 쪽을 고른다.

## 시스템 구성과 메시지 흐름

&#91;embedded content: 역할과 메시지 · 관제 PC, FMS, 핑키, OMX\]

FMS는 관제 PC, 핑키와만 주고받는다. OMX는 관제 PC(팀원 담당)가 맡는다. 핑키는 약제실 정밀 주차가 끝나면 지금처럼 관제 PC에 직접 알린다(`/notify`).

배송 한 번의 순서:

1. 관제 PC가 FMS에 주문(병실, 약품)을 넣는다.
2. FMS가 묶음을 만들고 로봇을 고른 뒤, 관제 PC에 배정(로봇, 주문, 실을 개수 = 3 − 지금 실린 수)을 알린다. 오염 제거가 필요하면 POCKET을 먼저 들른다.
3. FMS가 예약한 만큼 구간을 내준다. 다른 로봇이 도킹 중이면 약제실 안 대기 자리에서 기다렸다가 정밀 주차한다.
4. 정밀 주차가 끝나면 핑키가 관제 PC에 알리고, FMS에는 `segment_done`을 보낸다. 관제 PC가 OMX에 적재를 지시하고, OMX는 핑키 위에 약을 내려놓는다.
5. 관제 PC가 FMS에 적재 완료(로봇, 개수)를 보낸다. FMS가 병실까지 구간을 내준다.
6. 병실에 도착하면 오염도를 올리고 `spin`을 내준다. 회전이 끝나면 그 주문은 배송 완료, 배터리 −10, 관제 PC에 알린다.
7. 다음 병실로 6을 반복한다. 배정된 주문을 모두 마치면 로봇은 대기가 된다. 여분이 남아 있으면 실은 채로 새 주문을 받을 수 있다.

지도는 지금 쓰는 주행 그래프(`graph/graph_spec.yaml` → `graph.yaml`)를 그대로 FMS로 옮긴다. 그래프의 엣지마다 이미 `zone`(예약 단위)이 붙어 있어서, FMS는 zone을 자원으로 보고 예약한다. 좌표는 그림 cm(왼쪽 아래 원점, y 위), 위치 = 라이다 중심.

대기 자리: 복도 서쪽 끝 x=20 차선 노드(`B1_20`, `B2_20`, `T1_20`, `T2_20`)는 모든 갈림목(x ≥ 40)보다 바깥이라 서 있어도 아무도 막지 않는다. 이미 그래프에 `role: wait`로 표시돼 있다. 보류 중인 왼쪽 1인실 2곳과 단일차선 협로(`deferred`)는 FMS도 빼고 시작한다.

물리 기준: 로봇 몸체 Ø11, 약을 실은 그릇 Ø14, 두 차선 간격 15cm. 빈 로봇끼리는 4cm, 빈 로봇+실은 로봇은 2.5cm 틈이 남고, 실은 로봇끼리는 1cm뿐이라 교행 금지 규칙과 맞는다.

**약제실 안 대기 자리** (그래프에 넣음, 2026-10-26). 앞 로봇이 OMX에 도킹해 싣는 동안 다음 로봇이 기다리는 곳이다. 카메라 정밀 주차 전 단계다.

- 자리: `PHARM_WAIT` (130, 180), 방향 180°(도킹 자리 쪽).
- 실제 벽(`real_walls.yaml`)에는 약제실과 오른쪽 4인실 사이 칸막이가 없다. 아래 벽(y=160)은 x 116\~144.5에서 끝난다. 약제실 문(x 79\~116) 안쪽에는 문틀 토막(왼쪽 10cm, 오른쪽 6cm)이 있다.
- 약제실 문으로는 못 들어간다. 도킹한 로봇(Ø14)과 오른쪽 문틀 끝 사이 빈자리가 14.4cm라, Ø11 로봇이 지나면 양쪽 틈이 1.7cm씩뿐이다. 처음 제안한 (120,172)도 이 문틀 끝에 닿는다.
- 그래서 오른쪽 4인실 문 앞 `GT175U` (175,162)에서 들어간다. 엣지 `GT175U → PHARM_WAIT` 48.5cm, 벽 여유 7.8cm(그릇 실으면 6.3cm).
- 복도와: 몸체 아래 끝 y 174.5 → 복도 경계 y=160에서 14.5cm 안쪽.
- 도킹 로봇과: 도킹 자리(98.9,178.8)의 실은 로봇과 틈 18.6cm. 도킹 로봇이 돌아 문으로 나갈 때도 닿지 않는다.
- 도킹 자리로: `PHARM_WAIT → PHARMACY` 31.1cm(벽 여유 8.5cm), Nav2로 간 뒤 정밀 주차.
- 경로 규칙:
  - 대기 → 도킹은 한 방향(`oneway`)이고, 도착지가 PHARMACY일 때만 쓴다.
  - 도킹 자리에서 나갈 때는 항상 약제실 문으로 나간다.
  - 다른 길이 대기 자리를 지름길로 쓰지 않는다(`wait_only`).
  - 그래서 지금 `/goto PHARMACY` 경로는 전과 같다.
- `GT175U`는 오른쪽 4인실 문 앞이다. 대기 자리로 갈 때 FMS는 `room4_r`도 함께 예약한다.
- 세 번째 로봇: `pharmacy_wait`도 차 있으면 약제실 구간을 받지 못하고, 주차 자리나 지금 자리에서 기다린다.
- 현장 확인: OMX 본체·팔이 (130,180) 근처까지 오는지, 실제로 칸막이가 없는지.

## 로봇 상태 모델

FMS는 로봇마다 아래 값을 들고 있다. 위치와 진행은 로봇이 보내고, 오염도·배터리·적재 수는 FMS가 규칙에 따라 바꾼다.

| 값 | 누가 바꾸나 | 언제 바뀌나 |
| --- | --- | --- |
| 위치 (x, y, heading), 가장 가까운 노드 | 로봇 보고 | 주기 보고 (하트비트 격) |
| 지금 구간, 구간 진행 | 로봇 보고 | 구간 시작·끝 |
| 적재 수 (0\~3), 그중 배정된 주문 / 여분 | FMS | 적재 완료(관제 PC가 알려 줌) 때 +k, 병실 회전 완료 때 −1 |
| 싣고 있음 | FMS | 적재 수 ≥ 1 (여분만 남아도) |
| 오염도 (0\~100) | FMS | 병실 도착 때 +10 / +50, POCKET 5초 뒤 0 |
| 배터리 (0\~100) | FMS | 병실 회전 완료 때 −10, CHARGER 도착 10초 뒤 100 |
| 예약한 자원 목록 | FMS | 구간을 내줄 때 잡고, 지나가면 푼다 |
| 상태 | FMS | 아래 상태 전이 |

상태는 8가지다: 대기, 이동, 적재 대기(약제실), 배송 회전(병실), 오염 제거(POCKET 5초), 충전, 비켜 주기, 연결 끊김.

배정된 주문을 모두 마치면 대기로 돌아온다. 여분이 남아 있으면 대기 중에도 ‘싣고 있음’이고, 새 주문을 받으면 약제실을 거치지 않고 바로 병실로 간다. 아래 세 상태는 대기에서만 들어가고 끝나면 대기로 돌아간다.

## 배차와 배송 묶음

새 주문은 먼저 여분을 실은 로봇에 끼워 넣을 수 있는지 본다. 안 되면 가장 오래 기다린 주문을 씨앗으로 약제실 묶음(최대 3건)을 만들어, 약제실에 가장 빨리 갈 수 있는 로봇에 맡긴다. 우선도가 없으므로 씨앗을 가장 오래된 주문로 잡아 뒤로 밀리는 주문이 없게 한다.

**약제실 묶음 배차 자격** (하나라도 안 맞으면 그 로봇은 후보에서 빠짐)

1. 상태가 대기이고 연결돼 있다.
2. 배터리 > 20 (약제실에 갈 수 있다). 20 이하면 충전으로 보낸다.
3. 들를 병실 수 × 10 ≤ 배터리 (배송 중 0 아래로 내려가지 않음).
4. 묶음을 다 돌았을 때까지 오염도가 한 번도 100을 넘지 않는다 (아래 미리 계산).

약제실에서 실을 개수 = 3 − 지금 실린 수. 배정 주문을 빼고 남는 것은 여분이다.

**여분 로봇에 끼워 넣기** (약제실을 안 거치므로 먼저 본다)

- 대상: 여분이 1개 이상인 로봇. 대기 중이든 배송 중이든 된다.
- 끼울 자리: 아직 안 간 방문 순서 중 경로가 가장 덜 늘어나는 곳.
- 조건: 끼운 뒤 남은 경로에서 오염도 ≤ 100, 남은 병실 수 × 10 ≤ 배터리, 수술실이면 진입 전 오염도 0(POCKET 경유). 배터리 > 20 조건은 약제실에 안 가므로 없다.
- 여러 로봇이 되면 늘어나는 거리가 가장 짧은 로봇.

**묶음 만들기와 미리 계산**

```python
CONTAM = {'1인실': 10, '4인실': 50, '수술실': 0}
CAP = 3                                     # 주문 1건 = 약 1개

def make_bundle(robot, orders):
    seed = orders.oldest()
    bundle, here = [seed], PHARMACY
    while len(bundle) < CAP:
        cand = orders.not_in(bundle).sorted_by(graph_dist(here, room))
        nxt = next((o for o in cand if fits(robot, bundle + [o])), None)
        if nxt is None: break
        bundle.append(nxt); here = nxt.room
    return bundle if fits(robot, bundle) else None

def fits(robot, bundle):
    c = robot.contam_at_start              # 출발 전 POCKET을 들르면 0
    b = robot.battery
    for room in visit_order(bundle):       # 같은 병실은 한 번 방문, 수술실 순서 규칙 적용
        if room == SURGERY and c > 0:
            c = 0                          # 수술실 앞에 POCKET 들르기를 경로에 넣음
        c += CONTAM[kind(room)]
        b -= 10                            # 병실 하나당
        if c > 100 or b < 0: return False
    return True
```

**로봇 고르기**: 자격이 있는 로봇 중 `약제실까지 그래프 거리 + (오염 제거가 필요하면 POCKET 경유 거리)`가 가장 짧은 로봇. 자격 있는 로봇이 없으면 주문은 기다리고, 다음 이벤트(새 주문, 로봇이 대기로 바뀜, 충전·오염 제거 끝)에서 다시 돌린다.

**수술실이 낀 묶음**: ① 오염도 0으로 출발(필요하면 POCKET 먼저) → 약제실 → 수술실 → 나머지 병실, 또는 ② 약제실 → 다른 병실 → POCKET 5초 → 수술실. 두 경로 길이를 비교해 짧은 쪽.

**제안**: 로봇이 대기 상태가 될 때 오염도가 0보다 크면 바로 POCKET으로 보낸다. 그러면 대부분 로봇이 오염도 0에서 배차돼 묶음을 크게 만들 수 있고 수술실 주문도 바로 받는다. 비용은 POCKET 왕복과 5초.

## 경로 계획과 통행 관리

FMS는 전체 경로를 그래프에서 계획하지만 로봇에는 예약에 성공한 구간까지만 내준다. 다음 구간을 못 잡으면 로봇은 지금 자리나 가까운 대기 자리에서 멈춰 기다린다.

**경로 계획**

- 지금 로봇에 있는 `api/graph_route.py`(그래프 최단 경로 + nav/wall/rotate/dock 구간 나누기)를 FMS로 옮긴다.
- 교행통로에서는 차선을 FMS가 고른다. 기본은 우측통행, 그 차선이 예약돼 있으면 다른 차선.
- 가중치 = 길이 + 예약된 자원을 지나면 벌점. 막힌 길을 피해 돌아갈 수 있으면 돌아간다.

**구간 예약 규칙**

1. 로봇에 구간을 내주기 전에 그 구간이 지나는 zone을 모두 예약한다. 하나라도 못 잡으면 아무것도 안 잡는다(전부 또는 없음).
2. 협로·계단 통로·막다른 방(병실, 약제실, POCKET/충전)은 **들어가는 구간 + 빠져나온 뒤 설 자리**까지 한 번에 예약한다. 막다른 방은 나올 때도 같은 문을 쓰므로 문 앞 갈림목을 나올 때까지 놓지 않는다.
3. 로봇이 zone을 벗어났다고 보고하면(구간 끝) 푼다.
4. 연결이 끊긴 로봇의 예약은 풀지 않는다.

**교행 판단 시점**: 싣고 있음은 배송 도중에 바뀐다. 그래서 교행통로 차선을 예약하는 순간의 싣고 있음으로 판단한다. 두 로봇이 모두 싣고 있고 마주 오면 그 복도는 차선 구분 없이 한 방향만 들어간다. 같은 방향으로 따라가는 것은 허용한다.

**여분의 영향**: 여분을 실은 로봇은 배송을 마쳐도 ‘싣고 있음’이다. 3대가 모두 여분을 들고 있으면 교행통로에서 서로 비켜 줄 수 없어 복도가 사실상 한쪽 방향 1차선처럼 된다. 시험에서 막힘이 많으면 ‘여분 없이 배정 주문만 싣기’를 설정으로 끌 수 있게 해 둔다.

**교착 막기**

- 대기는 항상 zone 바깥의 대기 자리에서 한다. 협로 안이나 막다른 방 문 앞에서 기다리지 않는다.
- 예약은 요청한 순서대로 주고, 아무도 움직이지 못하는 상황(서로의 다음 zone을 기다림)을 FMS가 감지하면 한 대를 대기 자리로 빼고 경로를 다시 만든다.
- 약제실:
  - 도킹 자리가 비어 있으면 약제실 문(`GT99U`)으로 바로 들어간다.
  - 차 있으면 오른쪽 4인실 문(`GT175U`)으로 `PHARM_WAIT`에 가서 기다린다(자원 모델 참고).
  - 나가는 로봇은 항상 약제실 문으로, 대기하는 로봇은 4인실 문으로 다니므로 둘이 문에서 마주치지 않는다.
  - 대기 자리까지 차 있으면 세 번째 로봇에는 약제실 구간을 내주지 않는다.

**넓은 구간(Nav2)의 간격**: Nav2는 라이다에 보이는 다른 로봇을 장애물로 보고 ‘collision ahead’로 멈춘다. 병실·수술실·계단 통로는 이미 zone당 1대라 마주칠 일이 없다. 남는 곳은 복도 갈림목과 차선이다. 차선 간격 15cm면 빈 로봇끼리도 틈이 4cm라, 교행 구간은 Nav2가 아니라 테이프 따라가기(line)로 달려야 한다.

## 노는 로봇 비키기

추천은 ‘대기 상태가 되면 주차 자리로 보내고, 그래도 길을 막으면 그때 비킨다’이다. 노는 로봇도 자기가 서 있는 노드의 zone을 잡고 있는 것으로 취급한다. 그러면 다른 로봇의 예약이 막히는 순간 FMS가 알 수 있다.

| 방안 | 하는 일 | 장점 | 단점 |
| --- | --- | --- | --- |
| A. 대기 자리로 보내기 | 배송을 마치고 대기가 되면 오염 제거 → 충전 또는 빈 주차 자리 순으로 보냄 | 단순하고 예측 가능 | 다음 주문이 곧 오면 걸어간 길을 되돌아옴 |
| B. 막을 때만 비키기 | 제자리에 있다가, 다른 로봇 경로가 그 zone을 지나야 하면 그 경로 밖 가장 가까운 빈 대기 자리로 보냄 | 쓸데없는 이동 없음 | 비키는 동안 요청한 로봇이 기다림, 연쇄로 비키기 필요할 수 있음 |
| A + B (추천) | A로 보내되 가는 길이나 자리가 없으면 제자리, 막으면 B | 통로가 대부분 비어 있음 | 주차 자리 수가 로봇 수보다 많아야 함 |

주차 자리 후보 (통행을 막지 않는 곳):

- `CHARGER` — 충전도 함께. 단, 나오려면 POCKET이 비어 있어야 한다.
- 복도 서쪽 끝 `B1_20`, `B2_20`, `T1_20`, `T2_20` — 모든 갈림목보다 바깥이라 막는 길이 없다. 단, 왼쪽 1인실(보류)을 열면 다시 봐야 한다.
- 주차 자리가 아닌 곳: POCKET(오염 제거용, 충전 출입구), START\_A(아래 복도 차선 위), 협로·병실·약제실.

로봇은 최대 3대이고 주차 자리는 5곳(CHARGER + 복도 서쪽 끝 4곳)이라 모두 세울 수 있다. 약제실 안 `PHARM_WAIT`는 도킹 차례를 기다리는 자리라 노는 로봇을 세우지 않는다.

## FMS API (로봇 · 관제 PC)

로봇 API는 ‘목적지로 가라(`/goto`)’에서 ‘이 구간들만 달려라(`/segments`)’로 바뀐다. 구간 형식은 지금 `/plan`이 돌려주는 `segments`(nav/wall/rotate/dock)를 그대로 쓴다. `/goto`는 수동 시험용으로 남긴다.

| 방향 | 주소 | 내용 |
| --- | --- | --- |
| FMS → 로봇 | `POST /segments` | `{task_id, seq, segments:[…]}`. 202 접수, 409 다른 구간 주행 중 |
| FMS → 로봇 | `POST /cancel` | 지금 구간 멈춤 (지금 그대로) |
| FMS → 로봇 | `POST /set_pose`, `GET /status` | 지금 그대로 |
| 로봇 → FMS | `POST /fms/robots/{serial}/events` | `segment_started` / `segment_done` / `segment_failed` + `task_id, seq, index, pose, time` |
| 로봇 → FMS | `POST /fms/robots/{serial}/heartbeat` | 1초마다 `pose, state, segment`. 3초 안 오면 FMS가 연결 끊김으로 봄 |
| 로봇 → 관제 PC | `POST /api/v1/robot/arrived` | 약제실 정밀 주차 끝 알림. 지금의 `/notify` 그대로 |
| 관제 PC → FMS | `POST /orders` | `{room, item}` → 주문 id. `GET /orders/{id}`로 상태 |
| 관제 PC → FMS | `POST /loaded` | `{robot, count}` 적재 완료 → FMS가 병실 구간을 내줌 |
| FMS → 관제 PC | 배정 · 주문 상태 | 배정 `{robot, orders, load_count}`, 주문별 `배정 → 적재 → 배송 완료`. 관제 PC가 받을 주소를 정하거나 `GET /orders`로 물어봄 |

FMS는 OMX와 직접 말하지 않는다. 관제 PC와 주고받을 주소와 본문은 팀원과 맞추면 된다. 위 표는 초안이다.

**로봇 쪽에서 바꿀 것**

1. `POST /segments` 추가. 구간마다 시작·끝·실패를 FMS에 보낸다.
2. 구간 종류 `spin` 추가: 병실에서 제자리 360° 회전. 끝나면 FMS가 그 병실 배송을 완료로 처리한다.
3. 구간 종류 `line` 구현: 차선 테이프 따라가기. 지금은 복도 가운데를 Nav2로 달려서 교행이 불가능하다.
4. 하트비트 보내기.
5. 도착 신호(`/notify` → 관제 PC)는 그대로 두되, `/goto`뿐 아니라 `/segments`의 약제실 `dock` 구간이 성공해도 보내게 한다.
6. 경로 계획(`graph_route.py`)은 FMS로 옮기고 로봇에는 `/goto` 시험용으로만 남긴다. 그래프 파일은 FMS 한 곳에서 관리하고 버전을 맞춘다.

POCKET 5초는 로봇에 새 기능이 필요 없다. FMS가 POCKET 도착 `segment_done`을 받은 뒤 5초 동안 다음 구간을 내주지 않으면 된다.

**다음 단계**

1. 로봇 한 대로 `PHARM_WAIT`까지 가고(4인실 문 경유), 거기서 PHARMACY 정밀 주차까지 실제로 달려 본다. 그래프는 넣었고, 로봇에는 다음에 켜질 때 반영한다.
